# GameShop — เว็บขายไอเท็มเกม / โค้ดเกม / ไอดีเกม

เว็บแอปพร้อมใช้: หน้าร้าน, ตะกร้าสินค้า, ระบบสมาชิก, ชำระเงินผ่าน **PromptPay QR** และ **กระเป๋าเงิน (Wallet)**, และหน้าแอดมินสำหรับยืนยันการชำระเงิน

## เทคโนโลยีที่ใช้
- Backend: Node.js + Express
- Database: **SQLite ผ่านโมดูลในตัวของ Node.js เอง (`node:sqlite`)** — ไม่ต้องติดตั้ง DB server แยก และ**ไม่ต้องคอมไพล์โค้ด C++ ตอน `npm install` เลย** (แก้ปัญหา error `node-gyp` / หา Python ไม่เจอที่มักเจอบน Windows)
- Frontend: HTML/CSS/JavaScript ธรรมดา (ไม่มี framework ให้ยุ่งยาก)
- QR พร้อมเพย์: สร้างด้วยไลบรารี `promptpay-qr` + `qrcode`

**ข้อกำหนด: ต้องใช้ Node.js เวอร์ชัน 22.5.0 ขึ้นไป** (แนะนำเวอร์ชัน LTS ล่าสุดจาก https://nodejs.org) เพราะ `node:sqlite` เพิ่งมีในเวอร์ชันนี้เป็นต้นไป ตอนรันจะเห็น warning สีเหลืองว่า "SQLite is an experimental feature" — เป็นเรื่องปกติ ไม่ใช่ error สามารถใช้งานต่อได้ตามปกติ

## วิธีติดตั้งและรัน

```bash
npm install
node server.js
```

เปิดเบราว์เซอร์ไปที่ `http://localhost:3000`

ค่าเริ่มต้น: มีบัญชีแอดมินให้อัตโนมัติ **แต่ร้านเริ่มต้นว่างเปล่า ไม่มีสินค้าตัวอย่าง** — เพิ่มสินค้าเองได้ที่หน้า "แผงแอดมิน" หลังล็อกอิน
- username: `admin`
- password: `admin1234`

**ควรเปลี่ยนรหัสผ่านแอดมินทันทีหลังติดตั้งจริง** (ตอนนี้ระบบยังไม่มีหน้าเปลี่ยนรหัสผ่าน ต้องแก้ผ่าน SQL โดยตรง หรือเพิ่มฟีเจอร์นี้เพิ่มเติม)

## ตั้งค่าพร้อมเพย์ของร้านคุณเอง

แก้ไขในไฟล์ `server.js` บรรทัด:
```js
const SHOP_PROMPTPAY_ID = process.env.PROMPTPAY_ID || '0812345678';
```
เปลี่ยนเป็นเบอร์โทรศัพท์หรือเลขบัตรประชาชนที่ผูกกับพร้อมเพย์ของร้านคุณ หรือจะตั้งผ่าน environment variable ก็ได้:
```bash
PROMPTPAY_ID=0898765432 node server.js
```

## ⚠️ ข้อจำกัดสำคัญที่ต้องรู้ก่อนใช้งานจริง

**เงินที่ลูกค้าโอน (ไม่ว่าจะจ่ายค่าสินค้า หรือเติมเงินเข้า Wallet) จะโอนเข้าบัญชีพร้อมเพย์ของร้านคุณโดยตรง 100%** — ตาม `SHOP_PROMPTPAY_ID` ที่ตั้งไว้ในไฟล์ `server.js` (เบอร์โทร/เลขบัตร ปชช. ของคุณเอง) เว็บนี้ไม่ได้ถือเงินไว้เอง ไม่มีบัญชีกลาง เงินไปที่บัญชีธนาคารจริงของคุณทันทีที่ลูกค้าโอน

ส่วน **"ยอด Wallet" ที่แสดงในเว็บเป็นแค่ตัวเลขบันทึกในฐานข้อมูล** (ไม่ใช่เงินจริงที่แยกเก็บไว้ที่ไหน) ใช้สำหรับให้ลูกค้าซื้อของในร้านนี้ได้เร็วขึ้นโดยไม่ต้องสแกน QR ทุกครั้ง ขั้นตอนคือ:
1. ลูกค้ากด "เติมเงิน" → ได้ QR พร้อมเพย์ → โอนเงินจริงเข้าบัญชีร้านคุณ
2. คุณ (แอดมิน) เห็นเงินเข้าในแอปธนาคารของคุณเอง → กด "ยืนยันรับเงิน" ในหน้าแอดมินของเว็บ
3. ระบบถึงจะบวกยอด Wallet ในเว็บให้ลูกค้าใช้ซื้อของต่อไป

**ระบบนี้ตรวจสอบการชำระเงินแบบ "กึ่งอัตโนมัติ" ไม่ใช่อัตโนมัติเต็มรูปแบบ**

QR พร้อมเพย์ที่สร้างขึ้นเป็นแค่ QR มาตรฐาน EMV ที่บอกยอดเงิน/ปลายทางให้ลูกค้าโอน — **เว็บไม่มีทางรู้เองว่าเงินเข้าบัญชีจริงหรือยัง** เพราะการเชื่อมต่อกับธนาคารเพื่อเช็คยอดเงินอัตโนมัติต้องสมัครใช้บริการ payment gateway ที่ได้รับอนุญาต เช่น:
- Omise / Opn Payments
- 2C2P
- SCB Easy API / KBank API (สำหรับร้านค้าที่จดทะเบียนกับธนาคาร)

ดังนั้นตอนนี้ flow คือ:
1. ลูกค้าสแกน QR โอนเงินจริง
2. **แอดมินต้องเข้าไปเช็คสลิป/ยอดเงินในแอปธนาคารเอง** แล้วกด "ยืนยันชำระเงิน" ในหน้าแอดมิน (`/#admin` หรือปุ่ม "แผงแอดมิน" ในเมนู)
3. ระบบจะปลดล็อกโค้ด/ข้อมูลไอเท็มให้ลูกค้าอัตโนมัติหลังยืนยัน

ถ้าต้องการให้ยืนยันอัตโนมัติจริง แนะนำให้ต่อยอดเชื่อม payment gateway ตัวใดตัวหนึ่งข้างต้น (ทีมงานเขาจะมี webhook แจ้งเมื่อเงินเข้า ค่อยเขียนโค้ดเรียก endpoint `/api/admin/orders/:id/confirm` อัตโนมัติแทนการกดมือ)

## โครงสร้างไฟล์
```
game-shop/
├── server.js          ← Express app + API ทั้งหมด
├── db.js              ← ตั้งค่า SQLite + ข้อมูลตัวอย่าง (สินค้า 3 รายการ)
├── package.json
├── public/
│   ├── index.html     ← หน้าเว็บทั้งหมด (SPA แบบง่าย)
│   ├── style.css
│   └── app.js         ← โค้ด JS ฝั่งหน้าบ้านทั้งหมด
└── shop.db            ← ไฟล์ฐานข้อมูล (จะถูกสร้างอัตโนมัติตอนรันครั้งแรก)
```

## ฟีเจอร์ที่มีให้แล้ว
- **แบนเนอร์โปรโมชันหลายอัน เลื่อนสลับกันได้อัตโนมัติ** (ทุก 4.5 วินาที) เพิ่ม/ลบได้จากหน้าแอดมิน ใส่รูปหรือไม่ใส่ก็ได้ (ถ้าไม่ใส่รูปจะใช้พื้นหลังไล่สีม่วงแทน) ตั้งลิงก์ให้กดแล้วเปิดหน้าอื่นได้
- **ระบบรีวิวร้านจริง** ลูกค้าที่ล็อกอินแล้วให้ดาว 1-5 + คอมเมนต์ได้ หน้ารีวิวแสดงคะแนนเฉลี่ยและรายการรีวิวทั้งหมด
- **หน้าติดต่อเราจริง** ตั้งค่า LINE ID, ลิงก์ Facebook, เบอร์โทร, เวลาทำการ ได้จากหน้าแอดมิน
- **ระบบเติมเงินแบบ wizard 5 ขั้นตอน** (เลือกช่องทาง → จำนวนเงิน → ชำระเงิน → ยืนยัน → สำเร็จ) รองรับช่องทาง "แบบสลิป" (พร้อมเพย์) ใช้งานได้จริง ส่วน "ซองอั่งเปา" (TrueMoney) แสดงเป็น "เร็วๆ นี้" — ต้องมีบัญชี TrueMoney Business + API Key ของร้านเองก่อนถึงจะเชื่อมต่อได้จริงในอนาคต
- **ระบบหมวดหมู่ย่อย**: ตอนเพิ่มสินค้า ใส่ "หมวดหมู่ย่อย" ได้ (ไม่บังคับ) เช่น เกม "Roblox Toy Code" อาจมีหมวดย่อย "ของแต่งตัว", "บัตรเติมเงิน" — แบนเนอร์แต่ละหมวดจะแสดง "N หมวดหมู่ · M สินค้า" นับจากหมวดย่อยที่ตั้งไว้จริง (ฐานข้อมูลเก่าที่ยังไม่มีคอลัมน์นี้จะอัปเดตให้อัตโนมัติตอนรันครั้งแรก ไม่ต้องลบข้อมูลเดิม)
- **อัปโหลดรูปสินค้าได้จริง** ตอนเพิ่มสินค้าในหน้าแอดมิน (jpg / png / webp / gif ไม่เกิน 5MB ต่อไฟล์) รูปจะถูกเก็บไว้ที่ `public/uploads/`
- ดีไซน์ธีมม่วง แบบร้านขายไอเท็มเกมทั่วไป: เมนู sidebar แบบ drawer, แถบค้นหา, ปุ่มตั้งค่า
- แดชบอร์ดสถิติหน้าแรก: จำนวนผู้ใช้งาน / ยอดขายรวม / สต็อกคงเหลือ / จำนวนครั้งที่ขาย (ดึงจากข้อมูลจริงในฐานข้อมูล ผ่าน `/api/stats`)
- สินค้าแนะนำ (การ์ดที่ติดป้าย HOT) + จัดกลุ่มสินค้าเป็นหมวดหมู่ตามชื่อเกม พร้อมแบนเนอร์และช่วงราคาต่อหมวด
- ราคาก่อนลด/หลังลดพร้อมป้าย "ประหยัดกี่บาท" (ตั้งค่าได้จากหน้าแอดมิน ช่อง "ราคาก่อนลด" และ "แสดงป้าย HOT")
- สมัครสมาชิก / เข้าสู่ระบบ (เก็บรหัสผ่านแบบ hash ด้วย bcrypt)
- หน้าร้าน: ค้นหา, กรองตามประเภท (ไอเท็ม / โค้ดเกม / ไอดีเกม)
- ตะกร้าสินค้า: เพิ่ม/ลบ/แก้จำนวน, เช็คสต๊อกไม่ให้เกิน
- Checkout 2 ช่องทาง: PromptPay QR (รอแอดมินยืนยัน) และ Wallet (หักยอดทันทีถ้าเงินพอ)
- เติมเงินเข้ากระเป๋า (Wallet) ผ่าน PromptPay QR เช่นกัน
- ระบบสต๊อกไอเท็มดิจิทัล: ใส่โค้ด/ข้อมูลไอดีล่วงหน้า ระบบจะจ่ายให้ลูกค้าทีละรายการอัตโนมัติเมื่อออเดอร์ถูกยืนยันว่าจ่ายเงินแล้ว (ไม่มีทางได้โค้ดซ้ำกัน)
- หน้าแอดมิน: เพิ่มสินค้าใหม่, ยืนยัน/ยกเลิกออเดอร์พร้อมเพย์, ยืนยัน/ปฏิเสธการเติมเงิน
- ประวัติคำสั่งซื้อของลูกค้า พร้อมแสดงโค้ด/ข้อมูลไอดีที่ซื้อไปแล้ว

## สิ่งที่ควรเพิ่มก่อนใช้งานจริงแบบเต็มรูปแบบ
- HTTPS (ใช้ reverse proxy เช่น Nginx + Let's Encrypt)
- เปลี่ยน `SESSION_SECRET` ใน `server.js` เป็นค่าสุ่มที่ปลอดภัย (อย่าใช้ค่า default)
- หน้าเปลี่ยนรหัสผ่าน / ลืมรหัสผ่าน
- เชื่อม payment gateway จริงเพื่อยืนยันการชำระเงินอัตโนมัติ (ดูหัวข้อข้างบน)
- Rate limiting กันสแปมสมัครสมาชิก/ล็อกอิน
- สำรองฐานข้อมูล (`shop.db`) เป็นประจำ
